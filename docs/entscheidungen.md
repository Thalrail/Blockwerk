# Entscheidungen Blockwerk (Stand 19.10.2026)
- Programmname: **Blockwerk**. Repo auf GitHub: Konto **Thalrail**, Repo **blockwerk** (eigenes, neues Repo; der Probeplaner bleibt unverändert).
- Server: Aternos, Bedrock. Bauwerke werden NICHT eingespielt/einkopiert, sondern von Hand nach Bauplan (Schicht für Schicht) gebaut.
- Oberfläche: ausschließlich Desktop, keine Handy-App. Gespielt wird auf der PS5, Blockwerk läuft auf PC/Laptop daneben als Bauplan-Bildschirm (Kompaktmodus aus Entfernung lesbar).
- Texturen: Faithful 32x (Bedrock-Fassung), Lizenzpflichten siehe `docs/ebenen.md`, Ebene 5.
- Ebenenmodell: `docs/ebenen.md` (Ebene 0–5 bestätigt).
- Seed: soll später einpflegbar sein (Platzprüfung: passt das Bauwerk an die Stelle, Gelände/Biom über Messpunkte).
- Leser (einzige KI-Stelle): zunächst über Claude-Chat (Briefing-Prompt -> JSON zurückkopieren). API-Schlüssel später optional.
- Tester: Jonah, jederzeit, auch mobil (Minecraft Pocket).
- Zitadelle-Bilder (14) legt Jonah im Repo unter `docs/zitadelle/bilder/` ab.
- Reihenfolge: allgemeine Engine zuerst, Zitadelle als Prüfstein.
- Neubeginn (19.10.2026): Blockwerk wird von Claude Code komplett neu nach dem Ebenenmodell umgesetzt. Der frühere M0/M1-Prototyp und Blockplan werden nicht übernommen.
- Technik: reines JavaScript (ES-Module), keine Abhängigkeiten, Tests mit `npm test` (Node 22), Seite über GitHub Pages ohne Build.
- Offen: Desktop-Umsetzung (eigene Desktop-App oder als Desktop-Fenster installierte Webseite).
- Arbeitsweg: Entwicklung mit Claude Code in der Cloud (claude.ai/code), Arbeit auf eigenem Branch, Abnahme per Pull Request durch Jonah.
- Sicherheit: Keine Zugangsschlüssel (Token, Passwörter) im Chat oder im Repo. Der GitHub-Zugang läuft über die Claude GitHub App.
- Aternos-Server (Angabe von Jonah, 20.10.2026): Simulationsdistanz **4 Chunks**, 20 Ticks pro Sekunde, Chunk 16×16. Steht in `data/server.json`.
- Händler (Angabe von Jonah, 21.10.2026): Dorfbewohner-Händler geben die Items beim Handel **direkt ins Inventar**, sie werden nicht gedroppt. Für Handels-Items ist also keine Auffang-Technik nötig. (Trichter für Lager und Sortierer der Zitadelle sind davon nicht berührt.)
- Wasser/Lava vor Trichter & Blockinhalten (Jonah, 21.10.2026): Als Nächstes in Ebene 1 kam Wasser/Lava.
- Java-Platzhalter für Wasser/Lava (Jonah, 21.10.2026): Die Fließ-Logik (Gefälle-Zählung, Abklingen, „erst nach unten“, Plus-Form um eine Quelle in der Luft) darf vorläufig der Java-Implementierung folgen, weil Bedrock nichts dokumentiert. Ausnahme zu „nie Java übernehmen“, gilt nur bis Jonah getestet hat; bleibt `ungeprüft`.
- Wasser/Lava-Logik (Jonah, 21.10.2026): Die Java-Logik (Gefälle bis zum 5. Block, Abklingen, erst nach unten, Plus-Form um eine Quelle in der Luft) „passt 1 zu 1, so funktioniert es auch in Bedrock“. Die Platzhalter-Ausnahme zu „nie Java übernehmen“ ist damit nicht mehr nötig. Bestätigt aus Erfahrung, nicht durch einen gezielten Spieltest: Status bleibt `ungeprüft`, bis er einen Test im Spiel meldet.
- Java als Ersatz, wo Bedrock schweigt (Jonah, 24.10.2026): Wo es für Bedrock keine ausdrückliche Angabe gibt, gilt die Java-Regel (Wiki, Java-Kategorien) als Platzhalter, mit Status `ungeprüft` und Quelle. Zeigt sich im Spiel ein Fehler (z. B. ein Lichtfehler), wird genau diese Stelle gezielt korrigiert, statt alles vorab zu testen. Ausdrückliche Bedrock-Angaben gehen immer vor. Erste Anwendung: Lichtfilter dünner Blöcke (Fackeln, Schienen, Zäune, Türen, Scheiben, Pflanzen … = wie Luft); Treppen und Halbstufen blockieren in Java nach Form: Blockwerk rechnet sie so (Filter 0, nur die vollen Flächen sperren; Jonah, 24.10.2026); Schnee, Pfade, Kolben bleiben unbekannt (Schranken). Fackel: Stärke 14, Reichweite 13 Blöcke (Wiki, von Jonah bestätigt, nicht im Spiel gemessen).
- Brüter und Dorfbewohner-Transport (Jonah, 25.10.2026): Der **Brüter** ist ein Dorfbewohner-Brüter (Vermehrung in einer Brutkammer). Ursprünglich sollten Bahnhof und Entladestelle die Dorfbewohner aus der Brutkammer per Lore in die Handelszellen fahren. Jonah hat in Bedrock festgestellt, dass der Berufsblock nicht an den nächsten, sondern an **irgendeinen** arbeitslosen Dorfbewohner geht (Wiki: erster Eintrag der gemeinsamen Liste). Folge: In der Brutkammer muss immer jemand beobachten, welcher Dorfbewohner losgeschickt werden muss. Der Brutkammer-Entwurf ist offen; Bahnhof, Entladestelle und Brüter werden bis dahin nicht gebaut (siehe `docs/offene-fragen.md`).
- Desktop-Umsetzung (Jonah, 25.10.2026): Blockwerk ist eine **Webseite** (GitHub Pages, ohne Build, keine Abhängigkeiten), in Chrome/Edge als eigenes Fenster installierbar; der Kompaktmodus nutzt das Always-on-top-Fenster des Browsers (Document Picture-in-Picture). Keine Electron-App.
- Reihenfolge der Oberfläche (Jonah, 25.10.2026): Bauplan zuerst (Schichtplan, Kompaktmodus, Material, Abhaken), danach 3D-Ansicht, Eingabe mit Rückfragen, Faithful-Texturen.
- Texturen (Jonah, 25.10.2026): Blockwerk arbeitet **grundlegend mit Faithful 32x (Bedrock)**, nicht erst mit Farbflächen. Im Repo liegen nur die benötigten Texturen (`data/texturen/`, einzeln aus dem offiziellen Faithful-Repo geladen, unverändert, mit Lizenzkopie und Nennung). Fehlende Texturen: markierte Ersatzfarbe.
- Live-Transport (Jonah, 25.10.2026): **eigener kleiner Dienst auf Cloudflare** (Worker + Durable Object, Anleitung `dienst/README.md`); im Raum liegen Haken und Planversion (Vorschlag mit Übernehmen). Für den eigenen Rechner gibt es einen Probedienst (`tools/live-lokal.js`). Keine Zugangsdaten im Repo; der Raum-Link ist der Zugang.
- Teilen und Live-Abhaken (Jonah, 25.10.2026): Freunde sollen einen Bauplan teilen und **live abhaken** können, wenn gebaut oder abgeändert wurde. Entschieden: **erst Teilen per Link oder Datei, Live später.** Der Fortschritt ist deshalb ein mischbares Datenmodell (je Schicht Abhaken mit logischer Uhr und Spielername, Schlüssel mit Abdruck der Schicht: ändert sich eine Schicht, verschwindet ihr Haken von selbst). Der Live-Transport (eigener Dienst, Firebase/Supabase oder WebRTC) wird mit Jonah entschieden, sobald 6b bis 6d stehen.
- Prüfstein Zitadelle (Jonah, 27.10.2026): Bilder liegen im Repo (`docs/zitadelle/bilder/`). **Stufe 1 = Hülle und Handel**, alles andere als offene Anfragen. Lager: 16 Kategorien × 3 Gegenstände. Lage „strahlenförmig“ im Vokabular. Die **Nische von Bild 07** (Lorenbahn von oben, Falltür, Wasserkanal) soll ein eigener Baustein werden; bis dahin plant der Prüfstein mit Blockwerks Nische (Reihenfolge der Arbeit: erst Last und Prüfbericht, dann der neue Baustein).
- Zitadelle, Nischenzahl (Jonah, 27.10.2026): **140 Handelsnischen** (sieben Viertel mit Ständen); die Kenndaten auf Bild 13 (8 × 20 = 160) stimmen nicht, es gibt kein achtes Viertel.
